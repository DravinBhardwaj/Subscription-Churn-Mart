
# System Architecture

## Project

Subscription Churn Mart

## Objective

Transform subscription customer data into reliable analytical
models and explain churn-risk indicators using engineered
SQL features.

## Data Flow

```text
Synthetic Data Generator
          |
          v
    CSV Source Files
          |
          v
   Python Validation
          |
          v
   SQLAlchemy Loader
          |
          v
     PostgreSQL
          |
          v
   Raw Source Tables
          |
          v
   SQL Staging Views
   -----------------
   stg_customers
   stg_subscriptions
   stg_usage
   -----------------
          |
          v
  customer_churn_mart
          |
          +---------------------+
          |                     |
          v                     v
    SQL Validation       Risk Explanation
          |               Rule-based / AI
          |                     |
          +----------+----------+
                     |
                     v
             Streamlit Dashboard
```

## Source Data

The project uses synthetic customer, subscription and
monthly usage data.

Source records are generated by:

    python -m app.generate_data

No personal or confidential company data is required.

## SQL Transformations

1. stg_customers: Customer attributes.
2. stg_subscriptions: Subscription details and churn status.
3. stg_usage: Monthly usage comparison.
4. customer_churn_mart: Final analytical customer-level view.

## Final Data Model

Grain: One record per customer.

Primary business key: customer_id.

The final view combines subscription status, payment
failures, monthly usage changes and risk indicators.

## Data Quality

Validation includes:

- Duplicate business key detection
- Invalid values
- Unsupported subscription statuses
- Invalid foreign key references
- Missing monthly usage records
- Duplicate rows in the final mart
- Consistency between subscription status and churn label

## AI Integration

AI receives engineered analytical features only.

It does not receive customer names, email addresses
or raw activity events.

The system uses deterministic explanations if no API
key is configured or if the AI request fails.

## Reproducibility

A fresh PostgreSQL database can be populated and
transformed with:

    python -m app.pipeline

The pipeline uses upserts for repeatable loading.
